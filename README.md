# Личная CRM

Записная книжка для людей, которых я знаю лично: кто это, откуда знакомы, телефон и почта, о чём договорились. Не для продаж — чтобы не терять людей и контекст общения с ними.

Что умеет:

- показывает список всех контактов по алфавиту;
- ищет по имени (регистр и «е/ё» не важны, слова можно в любом порядке);
- добавляет новый контакт — он сразу появляется в списке;
- в карточке контакта можно дописывать заметки после каждого разговора.

Идея и ограничения проекта — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что должно быть установлено

- [Node.js](https://nodejs.org/) версии 20.9 или новее
- [pnpm](https://pnpm.io/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных

## Первый запуск

1. Запустите Docker Desktop и дождитесь, пока он загрузится.
2. Скопируйте файл `.env.example` в `.env` и впишите значения: придумайте логин, пароль и имя базы (подробнее — в разделе «Настройки и секреты»).
3. Откройте терминал в папке проекта и выполните по очереди:

```bash
pnpm install      # скачивает библиотеки
pnpm db:up        # запускает базу данных в Docker
pnpm db:migrate   # создаёт таблицы в базе
pnpm db:seed      # по желанию: 1000 тестовых контактов
pnpm build        # собирает приложение
pnpm start        # запускает его
```

4. Откройте в браузере <http://localhost:3000>.

Чтобы остановить приложение, нажмите `Ctrl + C` в терминале. Данные при этом никуда не денутся: они лежат в базе.

## Обычный запуск

```bash
pnpm db:up
pnpm start
```

База обычно поднимается сама вместе с Docker Desktop, но `pnpm db:up` не повредит: если она уже работает, команда ничего не сломает.

## Если меняли код

Есть два способа посмотреть изменения:

- `pnpm dev` — режим разработки: страница сама обновляется после каждой правки. Работает медленнее обычного режима, это нормально.
- `pnpm build`, затем `pnpm start` — обычный режим: быстрый, но после каждой правки нужно собирать заново.

## Все команды

| Команда | Что делает |
| --- | --- |
| `pnpm start` | Запускает собранное приложение на <http://localhost:3000> |
| `pnpm build` | Собирает приложение (нужно после изменений в коде) |
| `pnpm dev` | Запускает режим разработки |
| `pnpm db:up` | Запускает базу данных в Docker |
| `pnpm db:migrate` | Применяет изменения структуры базы (миграции) |
| `pnpm db:generate` | Создаёт новую миграцию после правки `src/db/schema.ts` |
| `pnpm db:seed` | Добавляет 1000 тестовых контактов. Работает только на пустой базе: если контакты уже есть, ничего не меняет |
| `pnpm lint` | Проверяет код на типичные ошибки |
| `pnpm typecheck` | Проверяет типы |

## Как проверить руками

1. Откройте <http://localhost:3000> — виден список контактов и их количество.
2. Нажмите «Добавить контакт», заполните имя и сохраните — список прокрутится к новому человеку, строка подсветится жёлтым.
3. Введите его имя в поиск — он останется в списке один. Откройте карточку.
4. Напишите заметку и нажмите «Сохранить заметку» — она появится под формой с датой и временем.
5. Обновите страницу — заметка на месте.
6. Откройте тот же адрес в другом браузере — те же контакты и та же заметка.

## Тестовые данные

`pnpm db:seed` создаёт выдуманных людей. Чтобы никому случайно не позвонить и не написать, телефоны начинаются с несуществующего кода `+7 000`, а почта — на служебных доменах `example.com`, `example.org`, `example.net`.

## Настройки и секреты

Логин, пароль и имя базы лежат в файле `.env`. Он не попадает в git; образец без значений — `.env.example`.

Переменные в `.env`:

| Переменная | Что это |
| --- | --- |
| `POSTGRES_USER` | Логин базы данных |
| `POSTGRES_PASSWORD` | Пароль базы данных |
| `POSTGRES_DB` | Имя базы данных |
| `POSTGRES_PORT` | Порт базы на компьютере. Можно не заполнять — тогда 5432 |
| `DATABASE_URL` | Адрес, по которому приложение подключается к базе: `postgres://ЛОГИН:ПАРОЛЬ@localhost:ПОРТ/ИМЯ_БАЗЫ`. Можно не заполнять — тогда приложение соберёт его из переменных выше |

Первые четыре читает база в Docker (`compose.yaml`), приложение читает все.

## Если что-то не работает

- **«Не получилось загрузить данные»** — не запущена база. Запустите Docker Desktop, выполните `pnpm db:up` и нажмите «Попробовать снова».
- **Порт 3000 занят** — приложение уже запущено в другом окне терминала. Закройте то окно или остановите его через `Ctrl + C`.
- **После правок в коде ничего не изменилось** — в обычном режиме нужно заново выполнить `pnpm build` и `pnpm start`.

## Как устроен проект

| Где | Что |
| --- | --- |
| `src/app/` | Страницы: список (`page.tsx`), карточка (`contacts/[id]/page.tsx`), сохранение данных (`actions.ts`) |
| `src/components/` | Части интерфейса: список, поиск, форма контакта, заметки |
| `src/components/ui/` | Готовые элементы shadcn/ui: кнопки, поля, окно |
| `src/lib/` | Запросы к базе, проверка введённого, форматирование |
| `src/db/` | Структура таблиц (`schema.ts`), подключение, тестовые данные (`seed.ts`) |
| `drizzle/` | Миграции — история изменений структуры базы |
| `compose.yaml` | Описание базы данных для Docker |

С базой работает только сервер: браузер получает уже готовые данные и к базе не обращается.

Стек: Next.js (App Router), TypeScript, React, Tailwind CSS, shadcn/ui, PostgreSQL в Docker, Drizzle ORM, pnpm.
